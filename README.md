# BatchGitPull

一个 Windows 桌面小工具，用来批量对「总项目文件夹」下的多个 git 仓库执行 `git pull`。它还会定时检查每个仓库是否需要拉取、提交或推送。

一个总项目下常有十几个独立仓库，逐个右键「拉取」很麻烦，也很难一眼看出哪些仓库本地还有没提交、没推送的代码。BatchGitPull 打开目录就能列出所有仓库及其状态，勾选后可以一键拉取。

## 特性

- **单文件、零依赖**：只有一个 `batch_git_pull.pyw`，使用 Python 标准库和 tkinter，调用系统已安装的 `git`。不需要 pip，也不需要打包。
- **批量拉取**：自动扫描所选目录第一层的 git 仓库，可勾选、并发拉取（1–8 个同时进行），全程不卡界面、不弹黑窗。
- **安全**：默认 `--ff-only`，本地与远端分叉时直接报错，不会自动产生合并提交，也不会留下冲突中间态。工具只做 pull，不会执行 stash / reset / checkout / clean / push。
- **失败原因看得懂**：常见错误（本地改动冲突、分叉、认证失败、网络不通、无上游分支等）会归类成中文说明，同时保留完整命令和 git 原始输出，便于排查。
- **本地/远端状态**：定时执行 `git fetch` 并比较状态，直接显示每个仓库「待拉取 / 未推送 / 未提交 / 未跟踪」，不用先拉取就知道哪些仓库需要处理。
- **多目录切换**：记住最近 10 个目录和每个目录的勾选状态；窗口标题会显示当前目录名，同时打开多个窗口时，在任务栏也能分清。

## 环境要求

- Windows 10 / 11
- Python 3.10+（安装时勾选 tcl/tk，默认就是勾选的）
- Git for Windows，`git` 已加入 PATH

## 使用

### 图形界面

直接双击 `batch_git_pull.pyw`，也可以在命令行指定目录：

```bat
pythonw batch_git_pull.pyw D:\projects
```

1. 点「浏览…」选择总项目文件夹，或把路径粘贴到输入框后按回车。
2. 列表会显示各仓库的分支和「本地/远端」状态，需要处理的行显示为橙色。
3. 勾选要拉取的仓库（也可以用「选中待拉取」一键勾选），点「开始拉取」。
4. 结束后失败项会排到最前面。选中某行，下方会显示完整输出；右键菜单可以打开目录、复制说明或单独重试。

「本地/远端」列的含义：

| 文案 | 含义 |
|---|---|
| 已同步 | 与远端一致，工作区干净 |
| 待拉取 N | 远端有 N 个本地还没有的提交 |
| 未推送 N | 本地有 N 个还没推送的提交 |
| 未提交 N | 有 N 个已跟踪文件被修改（含已暂存） |
| 未跟踪 N | 有 N 个新文件还没加入 git |
| 冲突 N | 有未解决的冲突文件 |
| 无上游分支 / 游离 HEAD / 上游分支已删除 | 当前分支无法与远端比较 |
| 远端获取失败 | 网络或认证问题；此时「待拉取」数沿用上次获取的结果 |

只有**已勾选**的仓库才会被检查。不关心的仓库取消勾选即可：它不再 fetch，整行变灰，右下角汇总也不再统计它。重新勾选后会马上补查一次。

状态检查的时机：
- 打开目录后立即检查一次。
- 之后按「自动检查」设定的间隔检查，可选关闭、5、10、30、60 分钟，默认 10 分钟。
- 也可以随时点「检查状态」手动检查。
- 拉取结束后、从其他窗口切回本工具时，只刷新本地状态，不访问网络。

### 命令行

```bat
:: 批量拉取（有失败或超时时退出码为 1）
python batch_git_pull.pyw --cli D:\projects

:: 只拉取指定仓库，允许合并，并发 4
python batch_git_pull.pyw --cli D:\projects --only repo-a,repo-b --merge --jobs 4

:: 只检查状态，不拉取
python batch_git_pull.pyw --cli D:\projects --status
```

### 自测

```bat
python batch_git_pull.pyw --selftest
```

自测在临时目录里用本地 bare 仓库构造各种场景，不访问网络，也不触碰你的任何仓库。

## 说明

- 状态检查会对每个仓库执行不带参数的 `git fetch`（即 `git pull` 的前半步）。它只更新远端跟踪分支，不改动本地分支、工作区和暂存区；读取状态时使用 `--no-optional-locks`，不会和你在 IDE 或 TortoiseGit 里的操作争抢锁。
- 只检查各仓库**当前所在分支**，不切换分支，也不统计其他本地分支的未推送提交。
- 所有 git 命令都设置为非交互模式。凭证缺失时会直接报「认证失败」，不会卡住等待输入；请先用 TortoiseGit 或命令行手动拉取一次，把凭证保存好。
- 配置保存在 `%APPDATA%\BatchGitPull\config.json`，内容包括最近目录、勾选状态、并发数、检查间隔和窗口尺寸，不保存任何凭证。显示的输出中，URL 里的凭证部分会被脱敏。
